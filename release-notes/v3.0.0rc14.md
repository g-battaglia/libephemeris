## Sealed means LEB-only

In `mode=leb`, persisted ephemeris states come only from the active LEB files.
The runtime does not open DE/BSP kernels, planet-center subsets, registered or
automatic SPKs, Horizons, ASSIST, or a network socket. A missing or corrupt
canonical group is a provisioning error, and a core request outside every
available LEB interval raises `EphemerisRangeError`.

Calculations that need Skyfield's vector protocol now receive
`LEBVectorEphemeris`, an in-memory adapter over the same LEB reader. This closes
the former source gaps in topocentric fixed stars, `calc_pctr()`, `nod_aps()`,
and related event paths without duplicating their astronomy algorithms.

Deterministic analytical or Keplerian code remains available only where a
persistent LEB trajectory is not scientifically meaningful. Tracing identifies
that real source; it is never labelled as LEB.

## Highest-priority pinned LEB for each body and date

Manifest-authenticated discovery composes the tiers cumulatively and resolves every request
in this fixed order:

1. base — DE440s, 1850–2150;
2. medium — DE440, 1550–2650;
3. extended — DE441, its exact source interval.

The choice is per body and per date. A narrow, higher-priority artifact is used
where it covers the request; a broader tier is consulted only outside that
stored interval. Per-body coverage recorded in companion files remains
authoritative.

## Complete `data-v3` artifact set

The release regenerates five LEB2 groups (`core`, `asteroids`, `exotics`,
`apogee`, and `uranians`) for all three tiers. The fifteen files form one
immutable, SHA-256-pinned provisioning set. `base_core.leb2` and
`base_uranians.leb2` also ship in the wheel and are byte-identical to the
corresponding GitHub release assets. Artifact verification does not turn every
contained trajectory into a source-reviewed JPL state: each body keeps its
actual `precision_class` and reviewed flag.

Shared nutation, Delta-T, and fixed-star tables are stored once in each core;
named companions contain only their own body channels. This preserves the
lightweight modular design without changing any coordinate data.

Generation now fails closed at the real bounds of every JPL source. It does not
linearly extrapolate vectors to fill a requested range. Explicit offline
Horizons requests include boundary padding so their numerical edge guard can
still preserve the exact requested tier when the upstream source supports it.

Outer-planet channels store the system barycentres supplied directly by the
selected DE kernel, as declared by the LEB coordinate type. Optional
planet-centre BSPs and analytical centre-of-body models never affect official
artifact bytes; a non-sealed runtime may apply an independently sourced JPL
centre offset after reading the barycentric LEB state.

Extended exotic trajectories generated through ASSIST are explicitly
`precision_class=numerical-model`, not direct minor-body JPL ephemerides. Their
stored range is limited to the guarded common interval of the DE441 planet
file and `sb441-n16.bsp` (currently JD -1200493.5 to 5008210.5). Outside that
per-body interval, sealed mode reports the deterministic local model actually
used instead of relabelling it as LEB coverage.

`regenerate-leb.sh all` rebuilds, merges, verifies, converts, and verifies the
entire three-tier/five-group matrix from the pinned scientific sources.

## Compatibility

- `mode=auto` prefers the same best-by-date LEB chain, then retains its
  configured non-LEB fallback behavior.
- `mode=skyfield` and `mode=horizons` do not select LEB implicitly.
- Public calculation signatures and the existing source/precision tracing
  vocabulary remain compatible.
- The legacy `data-v2` release remains available for older library versions;
  rc14 pins only the new LEB2 artifacts to `data-v3`.
