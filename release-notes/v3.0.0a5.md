## Headline: review-driven correctness, lint, and documentation fixes

LibEphemeris 3.0.0a5 collects the fixes from an external code review of the
library. Every finding was verified against the current code before any change;
invalid or measure-zero findings were left untouched and documented. Modern
results for the planets, Moon, asteroids, nodes, and house cusps are unchanged —
the corrections affect specific edge cases and flag combinations.

## Correctness fixes

### Heliacal Moon brightness

The Schaefer sky-brightness model received the Moon's **illuminated fraction**
but converted it to a phase angle with a linear map `(1 - f) * 180°`. That
over-brightened gibbous phases (e.g. a 0.75-lit Moon was treated as 45° from
full instead of the correct 60°). The conversion now uses the exact geometric
relation `α = acos(2f - 1)`, so heliacal-visibility results under moonlight are
correct across all phases.

### Sidereal house cusp speeds

`houses_ex2` returned **sidereal** cusp/angle positions but sampled their
**velocities** on the tropical path, so under `FLG_SIDEREAL` the speeds did not
match the frame of the positions. The velocity samples now use the same
sidereal-aware path, so a chart's sidereal cusps and their rates of change are
self-consistent (the difference is the ayanamsa drift rate, ~0.137″/day).

### Horizons backend flag handling

- Analytical bodies (Mean Node, Mean Apogee) are dispatched **before** the
  `FLG_NONUT` rejection, so their nutation-free output is computed analytically
  instead of incorrectly falling back.
- Uranian-body speed components are zeroed when `FLG_SPEED` is not requested,
  matching the state-vector and analytical paths (callers no longer receive
  unrequested velocity data).

### Fixed-star sidereal speed

The ayanamsa finite-difference used for the sidereal speed correction is now
wrapped to the shortest arc before dividing. This removes a spurious ~360°/day
jump that could occur at extreme dates when the ayanamsa crosses 0°/360°.

### SPK auto-download re-registration

An SPK body is now re-registered when its resolved **(file, NAIF id)** pair
changes — not only when the file path changes — so a corrected target id or an
in-place re-download is reliably picked up by subsequent calculations.

### Aerosol extinction double-scaling

A directly supplied aerosol coefficient (`0 < value < 1`) is the final value at
the observer and is now returned without a second altitude scaling. Coefficients
derived from meteorological visibility or humidity still scale with altitude.
This matches the documented behavior of `calc_aerosol_extinction`.

### Native floats

The shared spherical-to-cartesian velocity helper now always returns native
Python floats, even when callers pass numpy scalars.

## Documentation and lint

- Corrected docstrings: extinction at or below the horizon returns `99.0`; the
  `set_sid_mode` default is Fagan/Bradley; the `houses_ex2` velocity path is
  documented as a centered finite difference; Google-style `Args`/`Returns`
  added to `_matches`, `_lterm_offset`, and `_parse_leap_seconds_iers`.
- The IERS ΔT lookup logs its fallback to Skyfield at debug level instead of
  silently swallowing the error.
- Ambiguous Unicode glyphs in comments/docstrings replaced with ASCII;
  intentional broad exception handlers annotated explicitly.

## Deliberately not changed

- The eclipse phase classification keeps its strict boundaries: the only
  concentric-disc partial case is the measure-zero `dctr == 0 ∧ rsun == rmoon`
  annular/total boundary, where the obscuration is already 100% and the
  singularity is already guarded; the boundaries are kept for exact agreement
  with the reference at the annular/total transition.

## Verification

Ruff clean on all touched files; no new type-check errors. Targeted suites pass
(Horizons backend, houses, Schaefer/extinction, heliacal), and standalone
numeric checks confirm the phase-angle, sidereal-velocity, native-float, and
speed-gating fixes.
