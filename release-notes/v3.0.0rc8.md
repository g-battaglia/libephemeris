## Headline

> **rc8 is a clean-room review and release-hardening pass over rc7.** It fixes
> context/backend edge cases found by adversarial verification, strengthens the
> physical-worktree and package-content gates, and makes the API documentation
> follow the live public export surface.

## Correctness / reference-API parity

- **Context TT/UT retflags.** `EphemerisContext.calc()` no longer acquires the
  UT default ephemeris bit when the caller supplied no explicit ephemeris flag;
  `calc_ut()` retains the measured UT default. The same normalization applies
  to the `ECL_NUT` pseudo-body.
- **Context backend fidelity.** Explicit Skyfield and Horizons modes bypass an
  already-cached LEB reader. Automatic and LEB modes continue to reuse the
  reader. Tracing no longer changes whether an SPK, ASSIST, or Keplerian path
  performs the calculation.
- **Context edge cases.** Topocentric Earth returns the expected zero vector on
  the LEB path, and incompatible barycentric/analytic-ephemeris flags raise the
  same error through context and module-level entry points.
- **Nakshatra boundaries.** `split_deg()` now uses the independently measured
  13°20′ segment representation and carries minutes/seconds consistently for
  floating-point values immediately around segment boundaries.
- **Pre-UTC Julian input.** `utc_to_jd()` maps Julian-calendar civil dates to
  the corresponding Gregorian instant before applying the pre-1972 UTC model,
  avoiding a calendar-dependent offset.
- **Trace source accuracy.** Successful module/context `calc()` / `calc_ut()`
  calls now replace stale entries for `ECL_NUT`, south nodes, asteroid aliases,
  lunar points, fixed stars, and planetary moons. Analytical, ERFA, Skyfield,
  LEB, SPK, and mixed fixed-star paths remain distinct, and failed
  post-processing does not claim a successful backend.

## Backend and dependency isolation

- The developer CLI now forces Skyfield mode for every Skyfield test subgroup,
  preventing an ambient LEB configuration from silently exercising a different
  backend.
- SPK acquisition and cache tests exercise the production direct-HTTP path with
  isolated synthetic fixtures instead of stale local files.
- `astroquery` is no longer a core runtime dependency. It remains available in
  the `stars` and `dev` extras for catalog-building and validation workflows.
- The repo-only developer CLI anchors relative paths to the checkout, so its
  generated shell wrapper works outside the repository. Bash and fish now
  parse Click completion records instead of exposing metadata as candidates.
- LEB2 conversion exposes every canonical tier/group combination; tier
  verification explicitly checks the named core companion against LEB1 and
  reports Cartesian position-component error in AU. Core end-to-end precision checks
  fail closed on missing inputs, calculation errors, or absent body coverage.
  LEB1 generation now also exposes the exotic registry as a direct per-tier
  command.

## Public API and documentation

- `libephemeris.__all__` now includes `reset_session()`, documented performance
  and eclipse helpers, planetary-moon IDs, and the complete explicit public
  constants surface.
- The Sphinx API reference is generated from the live top-level export list,
  replacing a large hand-maintained directive list that could drift from the
  actual package.
- Focused contract tests verify that public exports resolve, retain their
  signatures, and provide usable docstrings. Missing lunar-node, Delta T, and
  occultation return-value details were filled in.
- Stale architecture, testing, backend, optional-dependency, and manual text was
  aligned with the current implementation and command surface.

## Clean-room and packaging hardening

- `scripts/check_provenance.py` now scans the physical worktree, including
  ignored and untracked paths, for prohibited reference-distribution artifact
  names. This supplements tracked-source fingerprints, SPDX checks, and shipped
  data-license validation.
- The orbital-elements parser suite uses a neutral filename and synthetic
  fixtures; no external reference-distribution data is required.
- Packaging tests verify explicit data namespaces, required CSV/LEB assets,
  optional dependency boundaries, and the absence of prohibited artifacts in
  both wheels and source distributions.
- Archive audits apply the same case-insensitive clean-room filename and
  directory rules as the physical-worktree gate.
- The content sweep detects UTF-8 text independently of filename suffix and no
  longer excludes the validation subtree; infrastructure exclusions are exact
  paths rather than reusable directory names.
- Archive audits consume tar/ZIP type metadata, reject special members, and
  scan safe-named text payloads. Forbidden names are rejected before payload
  inspection.
- Release notices state that reference-distribution source and data artifacts
  must not be stored in the source tree or distributed package.

## Compatibility

- No breaking changes versus `3.0.0rc7`.
- The canonical bare-name API remains the supported compatibility surface.
- Existing `calc()`/`calc_ut()` callers may observe corrected retflags, errors,
  or tracing source tags only in the edge cases described above.
