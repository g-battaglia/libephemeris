## Scientific behavior

- **`SIDEREAL | J2000` uniform for lunar points.** `FLG_J2000` is honored for
  every lunar point through one pipeline (precess to J2000, subtract the
  mean ayanamsha), keeping |TrueNode − MeanNode| physically bounded at every
  epoch. LEB and Skyfield agree to the microarcsecond.
- **Pole-angle mean obliquity.** The public of-date mean obliquity is the
  angle between the Vondrák precession poles, so precession and every
  equator↔ecliptic rotation share one self-consistent frame; the Sun's
  of-date ecliptic latitude stays ~0 at every epoch. Modern-era output is
  unchanged (< 0.001″ across 1900–2100).
- **Pure `deltat_ex`.** Delta-T queries no longer mutate the value exposed by
  `get_tid_acc()`; the flag-selected tidal acceleration is applied to the
  returned value only.
- **Bounded eclipse obscuration.** `attr[2]` reports the fraction of the
  solar disc covered (exactly 1.0 during totality); the > 1 disc area ratio
  stays derivable as `attr[1] ** 2`.

Each of these is documented with its rationale in
`docs/comparison/intentional-divergences.md`.

## Correctness / reference-API parity

- **Context TT/UT retflags.** `EphemerisContext.calc()` no longer acquires the
  UT default ephemeris bit when the caller supplied no explicit ephemeris flag;
  `calc_ut()` retains the measured UT default. The same normalization applies
  to the `ECL_NUT` pseudo-body.
- **Context backend fidelity.** Explicit Skyfield and Horizons modes bypass an
  already-cached LEB reader. Automatic and LEB modes continue to reuse the
  reader. Tracing no longer changes whether an SPK, ASSIST, or Keplerian path
  performs the calculation.
- **Context edge cases.** Topocentric Earth returns the expected zero vector on
  the LEB path, and incompatible barycentric/analytic-ephemeris flags raise the
  same error through context and module-level entry points.
- **Nakshatra boundaries.** `split_deg()` now uses the independently measured
  13°20′ segment representation and carries minutes/seconds consistently for
  floating-point values immediately around segment boundaries.
- **Pre-UTC Julian input.** `utc_to_jd()` maps Julian-calendar civil dates to
  the corresponding Gregorian instant before applying the pre-1972 UTC model,
  avoiding a calendar-dependent offset.
- **Trace source accuracy.** Successful module/context `calc()` / `calc_ut()`
  calls now replace stale entries for `ECL_NUT`, south nodes, asteroid aliases,
  lunar points, fixed stars, and planetary moons. Analytical, ERFA, Skyfield,
  LEB, SPK, and mixed fixed-star paths remain distinct, and failed
  post-processing does not claim a successful backend.
- **Planet-center coverage and speeds.** The medium center kernel now retains
  all ten JPL descriptors: Jupiter 1600–2200, Saturn/Uranus/Neptune 1550–2650,
  and Pluto 1800–2200. A speed stencil that reaches an outer coverage edge uses
  the same barycenter source on both samples, eliminating the former
  sign-changing spike. Internal descriptor boundaries remain on the physical
  center source.
- **Rejected center-cache performance.** An unchanged stale/unpinned
  planet-center SPK is hashed and warned about once per stat fingerprint;
  replacement, precision-tier changes, and `close()` force a fresh review.
- **Horizons analytical lunar points.** Mean node and mean apogee range checks
  no longer instantiate or download a 114 MB local DE440 kernel in Horizons
  mode.
- **Error contracts.** Historical hypothetical-body failures retain `body_id`,
  and the barycentric analytical-position error uses backend-neutral wording.

## Backend and dependency isolation

- The developer CLI now forces Skyfield mode for every Skyfield test subgroup,
  preventing an ambient LEB configuration from silently exercising a different
  backend.
- SPK acquisition and cache tests exercise the production direct-HTTP path with
  isolated synthetic fixtures instead of stale local files.
- `astroquery` is no longer a core runtime dependency. It remains available in
  the `stars` and `dev` extras for catalog-building and validation workflows.
- The repo-only developer CLI anchors relative paths to the checkout, so its
  generated shell wrapper works outside the repository. Bash and fish now
  parse Click completion records instead of exposing metadata as candidates.
- LEB2 conversion exposes every canonical tier/group combination; tier
  verification explicitly checks the named core companion against LEB1 and
  reports Cartesian position-component error in AU. Core end-to-end precision checks
  fail closed on missing inputs, calculation errors, or absent body coverage.
  LEB1 generation now also exposes the exotic registry as a direct per-tier
  command.
- The regenerated medium planet-center asset is published at SHA-256
  `d3c34f5efe9223ef588ec59a8c59c1bd6619b0eab5d5e0b35c353d675efe7b4d`
  (200,535,040 bytes). Fifty endpoint/midpoint position-and-velocity checks
  match the hash-recorded JPL source kernels exactly.

## Public API and documentation

- `libephemeris.__all__` now includes `reset_session()`, documented performance
  and eclipse helpers, planetary-moon IDs, and the complete explicit public
  constants surface.
- The Sphinx API reference is generated from the live top-level export list,
  replacing a large hand-maintained directive list that could drift from the
  actual package.
- Focused contract tests verify that public exports resolve, retain their
  signatures, and provide usable docstrings. Missing lunar-node, Delta T, and
  occultation return-value details were filled in.
- Stale architecture, testing, backend, optional-dependency, and manual text was
  aligned with the current implementation and command surface.
- The precision-tuning guide now matches strict mode: mapped minor bodies use
  registered or auto-downloaded JPL SPKs by default, and lower-precision
  Keplerian propagation is an explicit fallback.
- Configuration help and generated TOML cover the Delta T selector and LEB
  mmap preload range. English and Italian examples now use the live eclipse,
  occultation, refraction, and heliacal keyword names.
- LEB cache/lifecycle, lightweight session reset, Fagan/Bradley default,
  long-term user ayanamsha, and required PyERFA/nutation descriptions now match
  the implementation.
- Historical hypothetical-body IDs 40–58 calculate again through the shared
  analytical registry in Skyfield, Horizons, auto, and LEB modes. The module
  constants `VULCAN_ELEMENTS`, `WALDEMATH_ELEMENTS`,
  `PICKERING_PLANET_X_ELEMENTS`, `URANIAN_KEPLERIAN_ELEMENTS`, and
  `TRANSPLUTO_KEPLERIAN_ELEMENTS` are populated again.

## Provenance and packaging hardening

- Mean node/apogee use ERFA's implementation of the IERS 2003 Delaunay
  arguments and conventional inclined-orbit geometry.
  Interpolated apogee/perigee retain the Delaunay-series behavior with a
  correction table pinned by SHA-256 integrity checks.
- Every predefined ayanamsha ID 0–46 derives from its author's published
  defining statement — a (value, epoch) pair propagated with the project's
  Vondrák Method-B model, the same contract as `SIDM_USER` — regenerated by
  `scripts/generate_ayanamsha_definitions.py`. The galactic-center family
  follows the VLBI Sgr A* position (Reid & Brunthaler 2004) against its
  published target longitudes; no mode carries a fitted anchor. Per-mode
  sources are in `docs/reference/ayanamsha.md`.
- Hypothetical-body IDs 40–58 are built-in with per-row source annotations.
  Per-body source status is
  documented in the source record.
- Extended refraction uses an ICAO Standard Atmosphere ray tracer; heliacal
  observer corrections use published pupil/optics relations; eclipse contacts
  and shadows use physical disc/cone geometry; and ayanamsha modes use
  published zero points, catalog targets, IAU precession, or an explicitly
  published zero point or documented convention. All correction models are
  derived from published standards.
- `scripts/check_provenance.py` now scans the physical worktree, including
  ignored and untracked paths, for prohibited reference-distribution artifact
  names. This supplements tracked-source fingerprints, SPDX checks, and shipped
  data-license validation.
- The provenance sweep also rejects unannotated high-precision float literals
  (10+ significant digits) in shipped modules: every such constant must cite
  its published source inline or live in a module regenerated by a committed
  generator. The check runs over the entire `libephemeris` package.
- Reachable-history findings no longer suppress the independent worktree
  content scan; the report always shows physical-name, history, and content
  classes separately.
- Five path classifications inherited from target commit `fdd0fe6` and the
  published `v3.0.0a5`/`v3.0.0a6` ancestries are hash/ancestry-pinned and
  reported separately. The gate remains fail-closed for the same names in any
  later project commit and for every unlisted history finding; local
  orchestrator checkpoint refs are excluded as infrastructure.
- The orbital-elements parser suite uses a neutral filename and synthetic
  fixtures; no external reference-distribution data is required.
- Packaging tests verify explicit data namespaces, required CSV/LEB assets,
  optional dependency boundaries, and the absence of prohibited artifacts in
  both wheels and source distributions.
- Archive audits apply the same case-insensitive clean-room filename and
  directory rules as the physical-worktree gate.
- The content sweep detects UTF-8 text independently of filename suffix and no
  longer excludes the validation subtree; infrastructure exclusions are exact
  paths rather than reusable directory names.
- Archive audits consume tar/ZIP type metadata, reject special members, and
  scan safe-named text payloads. Forbidden names are rejected before payload
  inspection.
- Release notices state that reference-distribution source and data artifacts
  must not be stored in the source tree or distributed package.
- Contributor instructions prohibit inspecting or copying reference source,
  comments, documentation prose, algorithms, or data. Public API comparisons
  are ephemeral only: their numeric output may not be retained, fitted,
  transformed into data, or committed.

## Compatibility

- **Restored versus the initial rc8 review:** every predefined ayanamsha ID
  0–46 and hypothetical body ID 40–58 calculates again without the removed-mode
  warnings or `UnknownBodyError` regressions.
- `INTP_APOG` and `INTP_PERG` are anchored to the Moon's actual apsis
  passages in JPL DE440 (exact at every passage by construction), generated
  by the committed `scripts/generate_lunar_apse_model.py`. Ephemeral
  comparison with external implementations between passages stays within
  ~0.05° in longitude and `0.25°` in latitude; the distance channels carry
  the mean DE440 passage distances. Hosted LEB/LEB2 assets containing the
  interpolated-apse channels must be regenerated before publication.
- Default medium-tier installations again discover a hash-pinned bundled LEB
  fast path. `download_leb_for_tier()` and `download_leb2_for_tier()` resolve
  base, medium, and extended assets; pre-existing LEB1 and LEB2 files remain
  readable.
- `get_tid_acc()` retains the fresh-session public behavior of `-25.80`.
- No public rc7 export is removed. The canonical bare-name API remains the
  supported compatibility surface; existing callers may observe only the
  corrected retflags, errors, or tracing source tags described above.
