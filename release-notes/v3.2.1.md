# libephemeris 3.2.1

A one-line compatibility fix for the sealed `leb` mode refusal introduced in
3.2.0 for the interpolated lunar apsides.

## The model-window refusal reads like every other coverage refusal

In sealed `leb` mode 3.2.0 started refusing `INTP_APOG` / `INTP_PERG` outside
the fitted window of their packaged model (JD 2286820.5 to 2689310.5 /
2689316.5). The message said "is outside the fitted window [lo, hi] of the
packaged model that serves it", while every other coverage refusal of the
library says "is outside active LEB coverage range [lo, hi]". Consumers that
recognise a coverage miss by that fragment — and read the served window and
the requested Julian Day out of it — did not classify the new refusal.

The message now reads "Body 21 (intp. Apogee) at JD x is outside active LEB
coverage range [2286820.500000, 2689310.500000], the fitted window of the
packaged model that serves it. LEB mode does not silently substitute a
lower-precision source." Nothing else changes: same `EphemerisRangeError`,
same `start_jd` / `end_jd` / `requested_jd` / `body_id` attributes, same
condition, same behaviour in `auto`, `skyfield` and `horizons` modes.
