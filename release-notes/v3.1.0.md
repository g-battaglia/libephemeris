# libephemeris 3.1.0

Two related changes close the fictitious-body story opened by the sealed
runtime work in the 3.0.0 series: the sealed-mode warning flood for Uranian
bodies is gone, and the redundant `uranians` LEB companion is retired.

## Sealed mode no longer warns on fictitious-body dispatch

In `mode="leb"` every departure from the LEB fast path is reported at
WARNING, because a sealed deployment expects either an LEB-backed answer or
a declared local model. For fictitious bodies (IDs 40–58) the runtime
analytical model **is** the declared local source — there is no LEB channel
to depart from — yet the dispatch signal was classified as a degradation and
logged per body, per date, per call. Downstream consumers that pin sealed
mode (kerykeion does, by default) drowned in
`LEB body=40 … unavailable in sealed mode` lines
([kerykeion#240](https://github.com/g-battaglia/kerykeion/issues/240)).

The dispatch now raises the typed internal `FictitiousRuntimeDispatch`
(a `KeyError` subclass, so every caller contract is unchanged) and
`log_leb_fallback` classifies it at DEBUG in every mode. Genuine sealed-mode
degradations — a body missing from the file, an out-of-range date, corrupted
data — keep their WARNING severity.

## The `uranians` companion is retired

The Hamburg bodies (Cupido…Poseidon, IDs 40–47) were the only fictitious
bodies with a persisted LEB channel: `{tier}_uranians.leb2` companions
carrying a Chebyshev fit of the very same runtime propagation that computes
them (Neely 1980 element transcription in `libephemeris.hypothetical`).
The file reproduced the model to ~1e-9 deg and bought no measurable
end-to-end performance (median `calc_ut`: ~430 µs file-backed vs ~419 µs
pure model over 1500 samples). A source that can only ever equal the formula
it was sampled from adds a parallel code path, a per-file trust decision,
and three distribution artifacts per release — for nothing.

As of 3.1.0 the runtime analytical model is the only source for all
fictitious bodies, exactly as it always was for White Moon (56) and
IDs 48–58. Concretely:

- `download_leb2_for_tier` installs four groups per tier (`core`,
  `asteroids`, `exotics`, `apogee`): 4/8/12 cumulative files for
  base/medium/extended. The wheel bundles only `base_core.leb2`.
- Source tracing and `get_body_coverage` report `Analytical` / no coverage
  entry for IDs 40–47 (previously `LEB` when a pinned companion was
  attached). Positions move by at most the retired fit residual (~1e-9 deg).
- Legacy `*_uranians.leb*` files on disk are recognized by the tier guard
  and ignored; they can be deleted freely.
- The LEB format retires coordinate type 2 (`COORD_HELIO_ECL`) and the
  heliocentric pipeline; the value is reserved and will not be reused.

## Compatibility

Call signatures are unchanged; two observable outputs are not. Source
tracing for IDs 40–47 now reports `"Analytical"` where it previously
reported `"LEB"` whenever a pinned companion happened to be attached (an
environment-dependent label), and `get_body_coverage` returns no entry for
those ids. Code that asserted the previous outputs must accept the new
invariant answers.
