## Headline: LEB→Skyfield fallback for eclipse/occultation search loops (issue #19)

LibEphemeris 1.6.2 adds an automatic LEB→Skyfield fallback for eclipse,
occultation, and rise/transit functions whose iterative search loops
may probe dates outside the LEB file's coverage. With standard LEB files
(base 1849-2150, medium 1550-2650, extended ±13000) this fallback never
fires; it only activates with custom/partial LEB files shorter than the
search window.

No API changes. Fully backward-compatible.

## Background

PR #18 ported all eclipse/heliacal/fixed_stars functions from Skyfield to
the LEB fast path. The functions define LEB-backed inner closures inside
`if reader is not None:` blocks, then call them in iterative search loops.
If the search loop probes a date outside the LEB file's coverage,
`_topo_ecliptic()` raised `ValueError` with no fallback.

**Example flow before fix:**

```
sol_eclipse_when_loc(jd_start=2460000, ...)
  → reader = get_leb_reader()        # LEB covers 2024-2025
  → define _get_separation(jd)       # closure using _topo_ecliptic
  → search loop:
      → _get_separation(2460400)     # 2025-04 → OK
      → _get_separation(2460800)     # 2026-05 → ValueError!
                                     # No fallback to Skyfield
```

## Fix details

A new helper `_call_with_leb_skyfield_fallback(impl, ...)` runs `impl`
with `reader=<LEB>` first, and on `KeyError`/`ValueError` containing
"outside" retries with `reader=None` (forcing the Skyfield path).
Unrelated errors are re-raised.

Each affected function was split into a thin public wrapper and an
`_impl` (or pythonic) that takes `reader` as a keyword-only parameter.
The wrapper delegates to the helper.

## Tests added

`tests/test_leb_skyfield_fallback.py` (9 tests):

- **Unit tests for the helper:**
  - `test_no_reader_calls_impl_with_none` — direct Skyfield path when no LEB
  - `test_reader_available_no_error` — LEB path when LEB succeeds
  - `test_outside_range_triggers_skyfield_retry` — fallback on ValueError
  - `test_outside_nutation_range_also_triggers_retry` — nutation-range form
  - `test_unrelated_error_is_reraised` — does not swallow other errors
  - `test_keyerror_with_outside_message_triggers_retry` — KeyError variant

- **Integration tests (patch `fast_calc._topo_ecliptic` to simulate
  out-of-range):**
  - `test_sol_eclipse_when_loc_falls_back_to_skyfield`
  - `test_rise_trans_falls_back_to_skyfield`
  - `test_lun_eclipse_when_loc_falls_back_to_skyfield`

All integration tests verify the fallback produces a result close to the
baseline (LEB or Skyfield, whichever was active for the baseline call).

## Risk assessment

**Zero risk with standard LEB files** — all search windows fit within
base/medium/extended coverage. The fallback path is exercised only when
users supply custom LEB files shorter than the search window of the
function they invoke.

## Compatibility

No public API or behaviour change for callers using standard LEB files
or Skyfield-only mode. Callers using custom LEB files will see eclipse
queries that previously raised `ValueError` now return a Skyfield-based
result automatically.
