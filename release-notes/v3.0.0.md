## What changed in 3.0.0 (vs 3.0.0rc2)

### Extended-tier exotic minor bodies via N-body integration

The generator can precompute the `exotics` LEB group (Eris, Sedna, Makemake,
Haumea, and other distant minor bodies) for the **extended tier** through
REBOUND N-body integration seeded at a J2000 anchor from JPL SPK data, giving
deep-time coverage that Horizons cannot serve directly. The generation
pipeline reuses cached wider SPK kernels instead of forcing re-downloads. No
`exotics` companion is currently present in the release download manifest, so
users must generate or provide it separately.

### Final pre-release review fixes

A deep multi-agent code review of the full codebase before promotion to
stable produced the following fixes:

**Correctness / reference-API parity**

- `calc_pctr()` — both the module function and `EphemerisContext.calc_pctr()`
  — now honors the `FLG_XYZ` and `FLG_RADIANS` output-format flags
  (previously it always returned spherical degrees while echoing the flags
  in `retflag`). The same fix covers `EphemerisContext.calc_ut()`/`.calc()`
  on the non-LEB path; the output-format handling now lives in shared
  helpers used by every entry point.
- Fixed stars dispatched through `calc_ut()`/`calc()` (via the fixed-star
  offset) now delegate to `fixstar_ut()`, so `FLG_SIDEREAL`,
  `FLG_EQUATORIAL`, `FLG_SPEED` and `FLG_TOPOCTR` get the exact same
  handling as the dedicated entry point. Note the behavior change for
  `FLG_TOPOCTR`: it now raises `Error` when no observer position is set
  (previously the dispatch path silently returned geocentric coordinates).
- Calendar-flag validation (`invalid calendar` → `ValueError`, matching the
  reference binding) now also covers `utc_to_jd()`, `jdet_to_utc()` and
  `jdut1_to_utc()`; previously `cal=99` meant Julian in `julday()` but
  Gregorian in the UTC conversions — and in `utc_to_jd()` the interpretation
  even flipped across the 1972 boundary.
- Out-of-range dates on every fixed-star entry point now raise
  `EphemerisRangeError` (previously a generic `Error` hid the range cause).
- The `ECL_NUT` early-return path in `calc()`/`calc_ut()` now normalizes
  its retflag the reference's measured way — at most one ephemeris bit,
  `FLG_MOSEPH` kept and `FLG_SPEED3` not remapped — matching the reference
  API (`calc(flags=0)` → `0`, no default bit; `calc_ut` adds the default
  `FLG_SWIEPH`; `FLG_MOSEPH` echoed).
- Requesting angles without `set_topo()` or Arabic parts without
  `calc_angles()` now raises the library `Error` type instead of a bare
  `ValueError`, so `except libephemeris.Error` catches it.
- The planet-centric speed wrap-around detection now uses the same
  `180/(2*dt)` threshold as the geocentric path.
- SPK auto-download now pads requested coverage and rejects cached kernels that do
  not cover the requested dates. Pholus at 1900-01-01 is served from Horizons SPK
  and verifies to ~0.25" against Horizons; the remaining ~28" reference-API
  residual is documented as a certified historical-orbit difference.
- Heliacal detailed windows no longer collapse `jd3` onto `jd1`, fixed-star
  azimuth now uses the same convention as planet azimuth, and numeric string
  object names are no longer accepted as planet IDs.

**Validation**

- The validation harness now has a `CERTIFIED` verdict for documented,
  independently adjudicated divergences. Default runs accept those bounded
  differences; `--optional` reverts them to strict reference-API comparisons.
- New independent verifiers cover planetary MEAN apside speed derivatives,
  fixed-star distance/distance-speed channels, and the online Horizons check for
  Pholus at 1900-01-01.

**Robustness**

- Corrupted or truncated LEB/LEB2 files now consistently fail with a clear
  `ValueError` (which the LEB → Skyfield fallback handles) instead of leaking
  `struct.error` or cryptic numpy/zstd errors: bounds checks were added on
  the body index (both LEB1 and LEB2), the LEB2 chunk index, coefficient
  offsets, mmap chunk slices, and decompressed sizes, and error messages
  call out likely truncation. The fixed-star LEB path now falls back to
  Skyfield on corrupted data too, mirroring the planet path.
- LEB2 decompression is deduplicated across threads: concurrent requests
  for the same chunk/body wait on the in-flight decompression instead of
  redoing the zstd work (results were always correct; the eval memo cache
  stays lock-free under the GIL).
- `fetch_batch()` in the Horizons backend now logs the underlying cause when
  a parallel fetch fails permanently (rate limit, DNS, …) instead of
  swallowing it silently.
- IERS downloads write through a unique `mkstemp` temporary file, removing a
  cross-process race on a predictable `.tmp` path.
- N-body LEB generation re-checks anchor SPK coverage and forces a
  re-download when a previously registered kernel is too narrow for the
  J2000 anchor epoch (previously it could crash out-of-range mid-generation).
- SPK cache lookups during LEB generation now match the lowercased cached
  filenames on case-sensitive filesystems.

**Metadata**

- PyPI classifier promoted to `Development Status :: 5 - Production/Stable`.

## Upgrade notes

- No breaking API changes versus 3.0.0rc2.
- Code that caught `ValueError` from `calc_ut()` for missing `set_topo()` /
  `calc_angles()` preconditions should catch `libephemeris.Error` instead.
- `utc_to_jd()`/`jdet_to_utc()`/`jdut1_to_utc()` now raise `ValueError` for
  calendar flags other than `GREG_CAL`/`JUL_CAL` (previously such values
  were silently treated as Gregorian), matching `julday()`/`revjul()` and
  the reference binding.
- Fixed stars requested through `calc_ut()`/`calc()` with `FLG_TOPOCTR` now
  raise `Error` when no observer position is set (previously they silently
  returned geocentric coordinates); with `set_topo()` they now return true
  topocentric positions, consistent with `fixstar_ut()`.
