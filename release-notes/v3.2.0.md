# libephemeris 3.2.0

A hardening release. Every change closes a GitHub issue opened while the
public surface was being audited against its own documentation and against
the reference API; no value inside the documented domain of any function
moves, and the reference-parity campaign (kerykeion-parity, 5213 measures) is
identical before and after.

## `nod_aps` selects the model exactly as the reference does

`nod_aps()` / `nod_aps_ut()` chose the mean model for any `method` that did
not carry `NODBIT_OSCU` or `NODBIT_OSCU_BAR`, so values such as 8 and 16 —
non-zero low bytes that name no model — answered with mean nodes and apsides
where the reference answers with osculating ones. The selection rule now
matches the measured contract on every value of a 1560-point grid: mean when
`method & 0xFF == 0` or `NODBIT_MEAN` is set, osculating for every other
non-zero low byte. No validation is added; every integer is still accepted
([#78](https://github.com/g-battaglia/libephemeris/issues/78)).

## Sealed `leb` mode refuses the interpolated apsides outside their model

In `mode="leb"` the model-served lunar points (`MEAN_NODE`, `MEAN_APOG`,
`INTP_APOG`, `INTP_PERG`) were refused outside coverage only when the
requested frame happened to need nutation; with the default flags
`calc_ut(625673.5, INTP_APOG)` answered while `SUN` raised. The refusal now
depends on the date alone, and the interpolated apsides are additionally
bounded by the fitted window of their packaged model (JD 2286820.5 to
2689310.5 for the apogee, to 2689316.5 for the perigee — 1549-01-01 to late
December 2650 in TT), read from the residual-grid metadata, so it holds even
when only `base_core.leb2` is installed. Inside the window nothing changes;
`auto`, `skyfield` and `horizons` keep the documented edge taper
([#62](https://github.com/g-battaglia/libephemeris/issues/62)).

## Downloads are atomic

A failed repair could leave the user with less data than before: the cached
kernel, planet-centers table, LEB2 group, SPK or ASSIST file was unlinked
first and its replacement fetched afterwards. Every download now streams into
a temporary file next to its destination, the digest and the structural
validator run on that temporary file, and only a verified artifact is
published with `os.replace()`. Along the way `download_spk()` and
`download_and_register_spk()` honour `set_spk_cache_dir()` /
`LIBEPHEMERIS_SPK_DIR`, `reset_session()` clears the SPK body map, and
`libephemeris config` prints paths without touching the network
([#55](https://github.com/g-battaglia/libephemeris/issues/55)).

## Typed errors where the documentation promised them

- `StarNotFoundError` — exported and documented since 1.x, never raised — is
  now what every fixed-star lookup failure raises, with the identifier and
  the `search_type` that was attempted. It remains a subclass of `Error`
  ([#59](https://github.com/g-battaglia/libephemeris/issues/59)).
- Public entry points no longer leak standard-library exceptions: an int
  house-system selector that `chr()` rejects folds to the default like `999`
  does; `parse_orbital_elements("")` raises the documented
  `FileNotFoundError`; the calendar helpers raise their own `ValueError` for a
  non-string flag; the occultation functions fold a negative body id to the
  Sun, as the reference does, and raise the new exported `IllegalBodyError`
  (both `UnknownBodyError` and `ValueError`) for an unknown one
  ([#60](https://github.com/g-battaglia/libephemeris/issues/60)).
- `calc_airmass` raises `InputValidationError` for a method it does not
  implement instead of silently computing Kasten-Young; the contrast and
  visibility helpers do the same for an unknown explicit `eye_adaptation`,
  and accept `"scotopic"` as an input alias for `"dark"`
  ([#65](https://github.com/g-battaglia/libephemeris/issues/65)).
- `calc_eclipse_central_line` and the limit helpers no longer hang on a
  sampling step that cannot move the Julian Day: a non-positive or too-small
  `step_minutes` raises `InputValidationError`, a non-finite bound raises
  `EphemerisRangeError`
  ([#61](https://github.com/g-battaglia/libephemeris/issues/61)).

## Compatibility

Call signatures are unchanged. The only outputs that move are the ones the
issues describe: `nod_aps` for methods whose low byte names no model, sealed
`leb` mode outside the interpolated-apsis window, and the exception type
raised on the failure paths listed above — each new type is a subclass of the
type previously raised, so existing `except` clauses keep working.
