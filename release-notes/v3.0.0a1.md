## The 2026-06 full-project review fix series (WS0–WS12)

v3 also lands the complete review fix series. Most items are internal
corrections; the following **deliberately change observable behavior** to
match the Swiss Ephemeris reference or to correct measured errors. The full
inventory is in `CHANGELOG.md`; highlights:

- **Sidereal default**: the public ID remains Fagan/Bradley for API
  compatibility, but unsupported predefined modes warn and use the documented
  J2000 fallback. Native predefined modes are 17, 18, 19, 20, and 27.
- **Eclipses**: exact reference retflag bits and zero-filled cells; the
  invented `ECL_GRAZING` bit and local `ANNULAR_TOTAL` classification are
  gone; Besselian elements use the true equator of date with NASA sign
  conventions.
- **Error policy**: search/not-found raise `libephemeris.Error`; out-of-range
  raise `EphemerisRangeError`; `FLG_TOPOCTR` without `set_topo()` raises
  instead of silently returning geocentric.
- **Fixed stars**: `"Name,nomenclature"` return form, strict reference
  name-resolution, `FLG_TOPOCTR` honored; catalog rebuilt from public sources
  (1447 stars).
- **Bodies**: any numbered asteroid via `AST_OFFSET + N` (SPK → SBDB
  Keplerian fallback, now on the ecliptic of date); planetary moons via
  `PLMOON_OFFSET + NAIF`; unknown bodies raise `UnknownBodyError`.
- **Houses**: an independent harness (26 systems × 130-point grid) reports
  zero gated mismatches against the reference.
- **Packaging**: the `leph` dev CLI and `libephemeris.dev_cli` are no longer
  shipped in wheels (repo tooling only).

## Eclipse correctness (audit round v10)

- Solar-eclipse **obscuration is a true fraction in `[0, 1]`**: a total
  eclipse clamps to `1.0`, and a no-eclipse instant reports `0.0` from every
  entry point (it previously leaked a `1.0` fallback through
  `sol_eclipse_where` / `lun_occult_where`).
- The lunar-eclipse magnitude/contact helpers and `_lun_eclipse_how_pythonic`
  now route through the **single canonical shadow model** (they previously
  used a second model that disagreed by up to ~0.011 in magnitude and
  tens-to-hundreds of seconds in contact times).
- Solar-eclipse path width is characterized against NASA's Five Millennium
  Canon (documented agreement band, regression-guarded).

## Other corrections

- The plutino resonant libration argument uses the longitude of perihelion.
- The longitude-speed wrap-around correction is applied consistently across
  `planets`, `fast_calc`, and the independently sourced Harrington path.

## Installation

```bash
pip install --pre libephemeris==3.0.0a1
```

The `--pre` flag is required to install a pre-release. The wheels are
AGPL-3.0-only; for commercial terms contact the copyright holder
(see `LICENSING.md`).

## Compatibility

- **Python**: >= 3.12.
- **API**: the v2 canonical bare-name surface (no `swe_`/`SE_`/`SEFLG_`
  prefixes). 1:1 PySwissEph result compatibility is preserved except where a
  divergence is deliberate and documented in `docs/reference/divergences.md`.
- **Migration from v2**: if you store Arabic-part values, sidereal positions,
  or eclipse attributes computed with v2, re-check them against the deliberate
  behavior changes above before relying on them.

## Known limitations

- Interpolated apogee/perigee (bodies 21/22) remain a documented divergence
  from the reference.
- See `docs/reference/divergences.md` for the full catalog of inherent
  pyswisseph divergences (different ephemeris engines, delta-T models, etc.).
