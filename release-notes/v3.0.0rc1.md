## 1. Dual licensing & clean-room provenance

The defining change of v3 is **dual licensing**. The same codebase is offered
under either of two grants, and you choose the one you use it under:

- **Open source — `AGPL-3.0-only`.** Free for any use, including commercial, as
  long as you comply with the AGPL (notably network/distribution source
  disclosure). The wheels published on PyPI are AGPL-3.0-only.
- **Commercial — `LicenseRef-LibEphemeris-Commercial`.** For organizations that
  cannot or do not want to comply with the AGPL (closed-source products, SaaS
  without source disclosure). Arranged directly with the copyright holder.

To make the commercial grant defensible, v3 ships a **clean-room provenance**
footing:

- The Galilean satellite module (`moon_theories/galilean.py`) was rewritten
  clean-room from the published Lieske 1998 / Meeus ch. 44 theory, removing the
  last LGPL-3.0 component. Output is unchanged to floating-point re-association
  level (sub-nanometre per moon component over 1800–2200).
- The package now contains **no copyleft code**. The only third-party files are
  permissive (MIT): `vendor/spktype21.py`, `moon_theories/tass17.py`, and
  `moon_theories/tass17_data.py`.
- Provenance and licensing are enforced by local gates (`license:check`,
  `provenance:sweep`, `provenance:hypothetical`, `wheel:audit`), now extended to
  cover `docs/` and `scripts/`, with a third-party zero-hit class and a published-source
  gate on the Uranian/Transpluto elements.

Owned source files carry the SPDX expression
`AGPL-3.0-only OR LicenseRef-LibEphemeris-Commercial`. See `LICENSING.md`,
`COMMERCIAL-LICENSE.md`, `THIRD_PARTY_NOTICES.md`, `NOTICE.md`, and
`docs/methodology/galilean-clean-room-2026-06.md` (process record since
removed from the tree; available in the repository history).

## 2. Long-term precession & obliquity (Vondrák 2011)

The apparent-place reduction now uses the **Vondrák, Capitaine & Wallace (2011)**
long-term precession model (A&A 534, A22), valid **±200,000 years**, instead of
the IAU 2006 precession polynomial that is only valid for a few centuries around
J2000.

- Implemented via PyERFA's reference `ltp`/`ltpb`/`ltpecl`/`ltpequ` routines
  (BSD/ERFA, clean-room); see `libephemeris/precession_vondrak.py`. It touches
  the LEB fast path, the Skyfield reference path, and the ecliptic-body / SPK /
  fixed-star paths uniformly.
- The Sun's longitude error at year −3000 drops from ~36″ to ~6″ (the residual
  being the underlying-ephemeris difference, which precession does not affect).
- **Modern results are unchanged to sub-milliarcsecond** (Vondrák ≡ IAU 2006
  near J2000), so the golden regression baselines were regenerated.
- The of-date mean obliquity is taken from the Vondrák poles **everywhere** —
  including the `ECL_NUT` pseudo-body, the galactic-frame sidereal modes, and the
  node/apside reduction — so the whole library shares one consistent
  precession+obliquity frame. This differs from the reference's reported obliquity
  by ≤ ~6″ only at deep-BCE dates, an effect confined to ecliptic latitude
  (longitude/ARMC unaffected) — a deliberate, documented scientific improvement.

See `docs/methodology/pyerfa-integration.md`.

## 3. Multi-era Delta T with a selectable model

Delta T (TT−UT1) is now a documented **piecewise multi-era** model governed by an
explicit priority chain, independent of the reference (copyleft) Swiss Ephemeris
(the library depends only on permissively-licensed ephemeris tooling, Skyfield/
pyerfa):

- New `set_delta_t_model()` / `get_delta_t_model()`, the
  `LIBEPHEMERIS_DELTAT_MODEL` environment variable, and the `deltat_model` TOML
  key select the model used after the user-defined / IERS-observed priorities.
- Two models: `smh2016` (**default**, Stephenson-Morrison-Hohenkerk 2016,
  obtained from Skyfield) or `espenak_meeus` (a self-contained native
  reimplementation of the NASA Espenak & Meeus 2006 polynomials).
- One consistent ΔT drives positions **and** house angles on every backend, so a
  chart stays accurate and self-consistent from antiquity to the far future.

See `docs/methodology/delta-t.md`.

## 4. Houses: long-term cusps & true cusp speeds

- House cusps now derive ARMC/sidereal time from the long-term Vondrák model via
  a stable geometric construction (`libephemeris/sidereal_longterm.py`); cusps
  that were off by up to ~3° at ±8000 years are now correct, while modern results
  are unchanged (sub-mas near J2000). One shared of-date obliquity is used by both
  the cusps and the position pipeline.
- `houses_ex2` reports **true time-derivative** cusp/angle speeds (centered 2 s
  finite difference of the full house solution) — markedly more accurate for the
  iteratively-solved Placidus/Koch systems near the polar circle than an analytic
  approximation; sign-locked systems (Whole Sign, Aries, Krusinski) report the
  guiding-point (Asc/MC) rate. Sidereal cusp speeds are sampled on the
  sidereal-aware path, so positions and speeds are frame-consistent.
- An independent clean-room harness (26 systems × 130-point grid) reports zero
  gated mismatches against the reference.

See `docs/methodology/sidereal-time-longterm.md`.

## 5. Eclipse / occultation / event correctness

A deep audit rebuilt the eclipse/occultation/rise geometry on shared canonical
cores and made the outputs match the reference exactly:

- Exact reference retflag bits and zero-filled cells; the invented `ECL_GRAZING`
  bit and local `ANNULAR_TOTAL` classification are gone; `when_loc` reports
  geometric contact times with visibility only in the `*_VISIBLE` bits;
  fabricated fallback contact times are now `0.0`.
- Besselian elements built on the true equator of date with NASA sign conventions.
- Solar-eclipse obscuration is a true fraction in `[0, 1]` (total clamps to
  `1.0`, no-eclipse reports `0.0` everywhere); the lunar-eclipse magnitude/contact
  helpers route through a single canonical shadow model.
- Backward (reverse-in-time) search for lunar eclipses and occultations;
  direction-aware `planet_occult_when_glob` / `lun_occult_when_glob`. Path width
  characterized and regression-guarded against NASA's Five Millennium Canon.

## 6. Fixed stars & bodies

- A **rebuilt 1,447-star catalog** from public sources (Hipparcos / VizieR /
  IAU-CSN), 116 cross-checked vs SIMBAD. Star functions return
  `"Name,nomenclature"`, use strict reference name-resolution, honor
  `FLG_TOPOCTR`, and return reference-style retflags; `fixstar2`/`fixstar2_ut`
  reach parity. Rigorous 3D space motion for proper motion on the LEB path.
- **Any numbered asteroid** via `AST_OFFSET + N` (SPK → SBDB Keplerian fallback,
  now on the ecliptic of date — removing a ~1290″ bias at 2026); unknown bodies
  raise `UnknownBodyError`.
- **Planetary moons** use canonical ids `PLMOON_OFFSET + NAIF` (Io 9501);
  unregistered moons raise; geocentric positions are apparent (light-time +
  aberration).
- `calc_planet_x_lowell` / `calc_planet_x_pickering` now return the canonical
  `calc()` position (Hoyt 1980 elements), removing a disagreement of up to ~158°;
  the plutino resonant argument uses the longitude of perihelion.

## 7. Backends: LEB & Horizons

- The live **Horizons** HTTP backend is now functional for planets, asteroids,
  analytical Mean Node/Apogee and Uranians, with consistent
  sidereal/XYZ/NONUT/speed framing.
- **LEB / SPK robustness:** corrupted-file handling and a zstd lock; LEB
  out-of-range raises `EphemerisRangeError`; LEB→Skyfield fallback for eclipse
  search loops; type-21 MDA-record cache keyed on `(target, center)` with a
  margin widened past worst-case light-time; light-time on heliocentric SPK paths.
- **ASSIST / COB** frame fixes (self-interaction, `propagate_trajectory` frame,
  particle-params dtype, COB normalization).

## 8. Error policy & API contracts

- Search/not-found conditions raise `libephemeris.Error` (was `RuntimeError`);
  LEB/ephemeris out-of-range raise `EphemerisRangeError`; `FLG_TOPOCTR` without
  `set_topo()` raises instead of silently returning geocentric.
- `utc_to_jd` / `jdet_to_utc` / `jdut1_to_utc` treat pre-1972 input as UT1 per
  their documented semantics.
- The **native-float contract** is enforced throughout: no `numpy` scalar leaks
  from public functions (heliacal dret tuples, eclipse `*_at_loc` helpers, the
  shared velocity helper).
- The default sidereal ayanamsha is Fagan/Bradley; interpolated apogee/perigee
  honor `FLG_NONUT`; node/apse speeds include the nutation rate; the
  longitude-speed wrap correction is applied consistently across `planets`,
  `fast_calc`, and the Uranian bodies.

## Migration from v2

The public API is the same v2 canonical bare-name surface — most code needs no
change. But several **observable behavior changes** are deliberate; if you store
or pin values computed with v2, re-check them against the upgrade list before
relying on them:

| Area | What changed |
|------|--------------|
| Sidereal | Default ayanamsha is now Fagan/Bradley — set `SIDM_LAHIRI` if needed |
| Eclipses | retflags / obscuration / lunar magnitude & contact times changed |
| Errors | not-found → `Error`; out-of-range → `EphemerisRangeError`; `FLG_TOPOCTR` without `set_topo()` raises |
| Fixed stars | `"Name,nomenclature"` form, strict resolution, `FLG_TOPOCTR` applied, catalog rebuilt |
| Remote epochs | Vondrák long-term precession/obliquity & sidereal time — modern results unchanged |
| House speeds | `houses_ex2` returns true time-derivative cusp speeds |
| Minor bodies | Keplerian fallback now on the ecliptic of date; planetary-moon ids `PLMOON_OFFSET + NAIF` |
| Planet X | `calc_planet_x_lowell/pickering` now match `calc()` |
| Packaging | `leph` dev CLI not shipped in wheels; `download all` prompts for confirmation |

See `docs/guides/migration-guide.md` and
`docs/comparison/intentional-divergences.md`.

## Installation

```bash
pip install --pre libephemeris==3.0.0rc1
```

The `--pre` flag is required to install a pre-release. The wheels are
AGPL-3.0-only; for commercial terms contact the copyright holder (see
`LICENSING.md`). Out of the box the wheel bundles a base-tier LEB2 core for the
14 core bodies (1850–2150); with the default `medium` tier the library
auto-downloads the additional data it needs on first use.
