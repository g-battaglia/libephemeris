## Correctness / reference-API parity

- **`calc()` (TT) ephemeris-bit echo.** `calc()` no longer forces the default
  `FLG_SWIEPH` bit into the returned retflag when the caller passed no explicit
  ephemeris bit (`calc(jd, body, 0)` echoes `0`); `calc_ut()` still adds the
  default. Applies to the normal-body path and the `ECL_NUT` pseudo-body.
- **`SIDM_GALALIGN_MARDYKS` (34) is a fixed-epoch frame mode.** Its sidereal
  output is a frame projection onto the mean ecliptic/equinox of the fitted
  epoch JD 2451079.771, plus a constant 30° longitude offset on the
  ecliptic/XYZ channels (the equatorial channel carries no offset) — matching
  the reference across planets, fixed stars and houses. A scalar-ayanamsha
  model reproduced only the longitudes and left the latitudes on the wrong
  plane (~24″ off in the 1940s).
- **Minor-body Keplerian fallback** now returns the true ecliptic of date,
  matching the SPK branch; the two previously disagreed by the nutation in
  longitude (~14″).
- **SPK type-2/3 asteroid path honours `FLG_TOPOCTR`** — a topocentric request
  on a registered type-2/3 kernel previously returned the geocentric place,
  dropping the diurnal parallax.
- **Houses Sunshine (`I`/`i`)** for dates outside the loaded ephemeris fall back
  to an analytic solar declination (Meeus ch. 25, ~0.01°) instead of silently
  substituting `sun_dec = 0.0` (which bent the cusps by degrees at high
  latitude); `i` (Makransky) stays distinct from `I` under the fixed-epoch modes.
- **`house_pos()`** in its objcoord-first form now honours an integer
  house-system code.
- **`split_deg()` nakshatra mode** reduces in the integer centisecond domain,
  removing a systematic one-arcsecond low bias in the seconds field.
- **`lun_occult_when_loc` / `lun_occult_where`** accept integer fixed-star ids
  (e.g. `REGULUS`) instead of raising a raw `KeyError`, matching
  `lun_occult_when_glob` and `calc_ut`.
- **Julian-calendar UTC output** (`jdut1_to_utc` / `jdet_to_utc`) keeps a
  `23:59:60` leap second instead of rolling it into the next day; a pre-1972
  `23:59:60` raises the plain `invalid time` message (the `(no leap second!)`
  suffix is reserved for the UTC era).
- **Fixed stars:** Spica's catalog radial velocity corrected (−22.85 → +1.0
  km/s); the `v1` star family resolves partial names by implicit prefix match;
  no legacy sidereal speed add-back for `SIDM_GALALIGN_MARDYKS`.
- **Topocentric Earth** returns the reference's zero vector on the LEB path.
- **Heliacal** phenomenon-visibility window survives a spike at the bracket edge.
- **Horizons** query values are URL-encoded (small-body `COMMAND` semicolons).
- **Fictitious bodies** zero the speed slots when `FLG_SPEED` is absent.

## Robustness

- The **ASSIST propagation cache** keys on the orbital-element values, not just
  the body name, so two different orbits sharing a name no longer collide.

## Documentation

- New **`docs/methodology/independence.md`** explaining what differs from the
  reference stack — data sources (JPL DE440/DE441 read directly), the IAU/ERFA
  + Vondrák 2011 reduction chain, the SMH-2016 ΔT model, the LEB / Horizons /
  context architecture — and how behavioural parity is established by black-box
  measurement.
- Documentation refocused on technical content; `NOTICE.md` is a compact
  attribution + calibration-disclosure notice.
- Freshness fixes: obliquity model (Vondrák, not IAU 2006), LRU cache sizes,
  the `fast_calc_tt` ΔT path, the Jupiter centre-of-body magnitude, and several
  stale links / anchors.

## Compatibility

- Public API unchanged; 1:1 reference parity preserved.
- No breaking changes versus `3.0.0rc6`.
